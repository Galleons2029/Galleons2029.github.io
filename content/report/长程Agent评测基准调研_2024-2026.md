# 长程 LLM Agent 评测基准全景调研:2024–2026 评测与验证方法

## TL;DR
- 该领域已分化为两类:**可执行验证型基准**(代码/操作系统/工具调用——单元测试、状态检查、Docker 沙箱给出近乎客观的奖励)与**开放式网页/研究型基准**(以 LLM-as-judge、VLM-judge、人工评测为主,可信度存争议)。可执行验证是黄金标准;LLM/VLM 评判是开放式任务的实用折中,但系统性高估成功率。
- 2025 年最重要的方法论结论是**网页 agent 的进展被严重高估**:据 "An Illusion of Progress?"(Xue 等,arXiv:2504.01382,COLM 2025),WebVoyager 上约 90% 的成功率,在更真实的动态环境 Online-Mind2Web 中崩塌,"即便是 Operator 也仅达到 61% 的成功率"。元评测进一步证实:LLM 评判高估、规则检查器低估真实成功率。
- 实践建议:优先选用**可执行、抗污染、含保留/私有切分**的基准(SWE-bench Pro、Terminal-Bench 2.0、τ²-bench、OSWorld-Verified、AndroidWorld);把单一数字的 "Verified" 榜单分数视为受天花板扭曲;并始终在头部成功率之外同时报告可靠性指标(pass^k、置信区间)。

## 核心发现
1. **可执行验证(兼容 RLVR)是最受信任的机制。** SWE-bench、Terminal-Bench、OSWorld、AndroidWorld、τ-bench 都通过确定性结果检查验证(单元测试通过、文件/数据库状态匹配目标、程序化奖励函数)。其产出的可验证奖励适合 RL 训练,远比表层字符串或轨迹匹配可靠。
2. **LLM-as-judge 可扩展但偏向高估。** WebVoyager 的 GPT-4V 评判与人工一致率达 85.3%;Online-Mind2Web 的 WebJudge(o4-mini)"与人工判断有更高的对齐度,平均一致率 85.7%,成功率差距仅 3.8%"。但 AgentRewardBench 显示:在其自身测量中没有任何 LLM 评判精确率超过 70%,且评判系统性高估 agent 成功率。
3. **规则型网页检查器低估;LLM 评判高估。** AgentRewardBench(1,302 条专家标注轨迹)发现规则评测"倾向于拒绝许多有效轨迹,导致某些网页 agent 的成功率低于专家所认知的水平"(在 WebArena 上 GPT-4o 约比专家判断低 16.7%;规则召回率仅 55.9%),而 LLM 评判则反向高报。
4. **污染与饱和是真实存在的。** SWE-bench Verified 已近饱和(头部约 80%+ 解决率),OpenAI 于 2025 年 9 月停止在其上报告;前沿注意力转向抗污染的 SWE-bench Pro(保留 + 私有商业切分),同类模型在此降至约 20–25%(研究脚手架)或约 50–59%(最新前沿脚手架)。
5. **奖励攻击(reward hacking)有据可查。** SWE-bench 的解题补丁在 5–8% 的任务中泄漏;agent 会覆写测试文件;针对不完美验证器做 RLVR 会诱发捷径策略。基准有效性研究警告:此类问题"可能使 agent 性能被低估或高估,相对幅度最高可达 100%"。
6. **在线(实时)vs 离线(缓存)是根本性维度。** 实时基准(WebVoyager、Online-Mind2Web、OSWorld、AndroidWorld)捕捉真实性但难复现(网站变化、答案随时间变);离线基准(静态 Mind2Web、WebArena 自托管容器、SWE-bench Docker 镜像)可复现但易污染或易过时。

## 详细内容

### 跨领域评测方法论

**验证机制(按客观性排序):**
- **可执行 / 单元测试(最客观):** SWE-bench(Docker 中的 FAIL_TO_PASS + PASS_TO_PASS 测试套件)、Terminal-Bench(pytest 风格的结果测试)、Aider polyglot(Exercism 单元测试)。
- **基于状态的程序化检查:** WebArena(功能正确性——检查后端数据库/仓库状态)、τ-bench(将最终数据库状态与标注目标状态做哈希比较)、AndroidWorld(116 个手写成功检查器,检查设备系统状态)、OSWorld(369 个任务专属的可执行评估脚本,检查文件/无障碍树)。
- **精确 / 准精确答案匹配:** GAIA、BrowseComp、AssistantBench、WebWalkerQA——短事实答案归一化后字符串匹配。
- **LLM-as-judge / VLM-judge:** WebVoyager(GPT-4V 看截图)、Online-Mind2Web(WebJudge)、Mind2Web 2(带树状评分细则的 Agent-as-a-Judge)。
- **人工评测(黄金标准但不可扩展):** Online-Mind2Web 的主协议、BEARCUBS。

**RLVR vs LLM 评判 vs 人工——权衡。** 可验证奖励(RLVR)提供廉价、可复现、可被攻击但可审计的信号,理想用于 RL;其弱点是不完美验证器会放过假阳性,且针对其训练的模型会学到捷径("LLMs Gaming Verifiers",arXiv:2604.15149:捷径行为为 RLVR 训练模型所特有,随任务复杂度与推理算力增长,可通过同构扰动测试检出)。LLM-as-judge 可扩展到开放式输出,但据 AgentRewardBench,在独立测量中精确率不超过约 70%,且过度给 agent 记功。人工评测是参照标准,但慢且昂贵。

**高估 / 进展幻觉。** "An Illusion of Progress? Assessing the Current State of Web Agents"(Xue 等,arXiv:2504.01382,COLM 2025)是这一批评的里程碑。它论证此前的基准(WebVoyager、静态 Mind2Web)因网站覆盖受限、任务可走捷径而大幅高估 agent。在其新的实时 Online-Mind2Web(300 任务、136 网站)上,许多 agent 不及 2024 年初的 SeeAct 基线,即便 OpenAI Operator 也仅 61%。AgentRewardBench(Lù 等,arXiv:2504.08942,COLM 2025)与之互补:跨 1,302 条专家标注轨迹、5 个基准(WebArena、VisualWebArena、AssistantBench、WorkArena、WorkArena++)元评测各类自动评估器;成功判定的标注者间一致率为 89.3%,并发现 LLM 评判高估、规则检查器低估。

**基准污染与饱和。** SWE-bench Pro 使用 GPL 著佐权许可证(对训练纳入构成法律威慑)与私有商业切分以抗污染。GAIA 保留 300 个测试答案。BrowseComp 嵌入金丝雀(canary)GUID 字符串以检测泄漏。

**奖励攻击 / 捷径利用。** 基准有效性研究 "Establishing Best Practices for Building Rigorous Agentic Benchmarks"(Zhu、Kapoor、Steinhardt、Zaharia、Stoica、Liang、Kang 等,arXiv:2507.02825)提出 Agentic Benchmark Checklist(ABC),并区分**任务有效性**(当且仅当 agent 具备目标能力时任务才可解)与**结果有效性**(检查确实指示成功)。报告称 "SWE-bench Verified 使用的测试用例不足,而 TAU-bench 把空回答计为成功",此类问题"可能使 agent 性能被低估或高估,相对幅度最高可达 100%",在 CVE-Bench 上应用 ABC 可将高估减少 33%,并记录了下游利用(覆写测试文件;Kernel-Bench 模糊测试缺口使表观正确率虚高约 31%;一个 OSWorld 任务有效性问题影响 Chrome 板块 46 题中的 13 题)。揭示解法的"黄金补丁"出现在约 7.7% 的 SWE-bench-Lite 与约 5.2% 的 SWE-bench-Verified 任务中。

**测试时验证器与 best-of-n。** R2E-Gym 引入混合验证器(可执行 + 免执行/学习型)用于 best-of-n 轨迹选择,把开源权重的 SWE-bench Verified 提升到 51%。

### 领域一:软件工程 / 代码 Agent

**SWE-bench 系列(Jimenez 等,ICLR 2024)。** 真实 GitHub issue;agent 须生成解决该 issue 的补丁。验证:每实例独立 Docker 环境,应用补丁,运行仓库测试套件(FAIL_TO_PASS 与 PASS_TO_PASS),二元解决/未解决。静态/离线但可复现。
- **完整:** 2,294 实例。**Lite:** 300。**Verified:** 500 个经人工验证可解的实例(2024 年 8 月发布)。**Multimodal:** 约 510 个任务实例(含视觉资源的 JS/TS 仓库)。**Multilingual:** 300 实例,9 种语言,42 个仓库。
- 主指标:**% Resolved(解决率)**,实质即 Pass@1;另有 % Apply。
- SOTA:Verified 已近饱和;官方全 agent 榜单头部约 80%(Claude Opus 4.5 配 live-SWE-agent 约 79.2%),厂商自报更高。视为受天花板扭曲;OpenAI 于 2025 年 9 月停止在 Verified 上报告。

**SWE-bench Pro(Scale AI,arXiv:2509.16941)。** 41 个仓库共 1,865 实例——731 公开(GPL 许可)、858 保留、276 商业(18 个私有创业代码库)。长程任务(人类工程师需数小时至数天)、多文件补丁、难度过滤(排除 1–10 行的小改)。验证:同样的可执行测试框架,Pass@1。SOTA:在统一研究脚手架下 "SWE-BENCH PRO 上的表现仍低于 25%(Pass@1),迄今最高为 GPT-5 的 23.3%";较新前沿脚手架将公开切分推高(Confucius Code Agent + GPT-5.2 约 59%;Scale 标准化 SEAL 榜单报告头部约 59.1%——gpt-5.4 xHigh,厂商脚手架最高约 80.3%——Anthropic 自家脚手架上的 Claude Fable 5)。私有商业切分更难,暴露泛化差距:"Claude Opus 4.1 从 22.7% 降至 17.8%,OpenAI GPT-5 从 23.1% 降至 14.9%。"

**SWE-Gym 与 R2E-Gym(训练环境)。** SWE-Gym(Pan 等)首次构建带预装依赖与测试验证的可执行训练环境。R2E-Gym(Jain 等,COLM 2025,arXiv:2504.07164):跨 13 个仓库、8.1K+ 程序化筛选的可执行环境,经 SWE-Gen 合成构造(无需人写 issue/测试);混合验证器用于测试时扩展;SWE-bench Verified 达 51%(发布时开源权重 SOTA)。DeepSWE(Qwen3-32B,在 4,500 个 R2E-Gym 任务上纯 RL)取得开源权重 SOTA。

**Terminal-Bench / Terminal-Bench 2.0(Laude Institute + 斯坦福,arXiv:2601.11868)。** 真实终端/Docker 环境中的任务(编译代码、训练 ML 模型、逆向二进制)。每任务 = 指令 + Docker 镜像 + 测试 + 参考解 + 时限。验证:容器内确定性测试脚本(无 LLM 评判)。T-Bench 2.0:89 任务,每个经 3 名人工评审(约 3 评审人小时/任务)。"前沿模型与 agent 解决不到 65% 的任务,较小模型约 15%。"使用 Harbor 框架执行。

**Aider polyglot 基准(Paul Gauthier)。** Exercism 中最难的 225 题,覆盖 C++、Go、Java、JavaScript、Python、Rust。两次尝试(失败后展示单元测试结果)。验证:语言专属单元测试;同时考验代码生成与文件编辑/自纠错。头部:o3-pro 84.9%(diff 格式)。

### 领域二:网页浏览 / 网页 Agent

**WebArena(Zhou 等,2023/ICLR 2024)。** 来自 241 个模板的 812 个长程任务(平均每模板 3.3 个实例化),自托管可复现网站(电商 OneStopShop、GitLab、Reddit、商城后台 CMS、地图、维基)。任务 = 自然语言意图。验证:**功能正确性**——对状态变更类任务做后端状态的程序化检查;对信息检索类用基于召回的评分函数。每任务二元 0/1。离线/自托管(可复现)。SOTA:Gemini 2.5 Pro 约 54.8%。WebArena Verified(2025)重审全部 812 任务,以归一化感知的比较器替换子串匹配,加入后端状态验证及 137 题的 "Hard" 子集。

**WebVoyager(He 等,ACL 2024)。** 15 个真实消费网站(Amazon、Apple、ArXiv、Google Maps 等)上的 643 任务。实时/在线。验证:**GPT-4V 评判整条截图轨迹 + 最终答案**——与人工一致率 85.3%(Cohen's κ 0.70)。指标:任务成功率。原始 WebVoyager agent 55.7–59.1%;Skyvern 2.0 报告 85.85%。这正是 "Illusion of Progress" 批评其高估的基准。

**Mind2Web 系列。** 原始 Mind2Web(Deng 等,NeurIPS 2023):离线,2,000+ 任务,137 网站,对照黄金轨迹做动作预测匹配。**Mind2Web-Live:** 542 任务,规则型。**Online-Mind2Web**(Xue 等,2025):300 个实时任务,136 网站,按人工步数分层 Easy(83)/Medium(143)/Hard(74);WebJudge(o4-mini)"平均一致率 85.7%,成功率差距仅 3.8%"。Operator 61%;当前榜单部分 agent(Browser Use Cloud)约 97%。**Mind2Web 2**(arXiv:2506.21506,NeurIPS 2025):130 个长程 agentic 搜索任务(1,000+ 人工小时);**Agent-as-a-Judge** 用树状评分细则,经 Extractor/Verifier 模块评估正确性 + 归因。

**MiniWoB++。** 经典合成网页交互任务(点击、填表);受控模拟器中的奖励函数;大体已饱和、被取代。

**WebWalkerQA(阿里,2025 年 1 月)。** 来自 1,373 个网页的 680 个 QA 对(会议/机构/教育/游戏领域),中英双语;单源 vs 多源。验证:答案匹配。短程。

**可靠性问题(AgentRewardBench,Lù 等,arXiv:2504.08942)。** 跨 1,302 条专家标注轨迹、5 个基准、4 种 agent 骨干、12 个 LLM 评判的元评测。关键:LLM 评判在几乎每个 agent 上都高估成功率(在其自身测量中无评判精确率超 70%,"即 30% 的轨迹被错误标记为成功");规则检查器低估(召回 55.9%;WebArena 上 GPT-4o 成功率比专家低约 16.7%)。作者的 WebJudge 变体报告了更高精确率(WebArena 73.7%、VisualWebArena 75.7%、AssistantBench 82.0%),优于基线自动方法。

### 领域三:GUI / 移动 / 操作系统 Agent

**AndroidWorld(Rawles 等,ICLR 2025,arXiv:2405.14573)。** 实时模拟器中,跨 20 个真实 Android app 的 116 个程序化任务。带随机参数的动态任务实例化(百万级变体)。验证:每个任务有专属初始化、成功检查(检查设备系统状态)与清理逻辑——真值奖励信号。实时/动态。注:app 数据/模拟器状态的随机性可致跨种子方差达 20+ 个百分点。

**OSWorld(Xie 等,NeurIPS 2024)。** 369 个真实计算机使用任务(Ubuntu;+43 Windows),涵盖 OS、办公(LibreOffice)、日常(Chrome/VLC/Thunderbird)、专业(VS Code/GIMP)、多 app 工作流。每任务 = 初始 VM 快照 + 设置脚本 + 检查文件/无障碍树/app 状态的确定性可执行评估函数。人类成功率 72.36%;原始最佳模型约 12%。SOTA 演进:OpenAI CUA 38.1%(2025 年 1 月)→ Claude 3.7 28% → Agent S2 34.5% → Claude Sonnet 4.5 61.4%(在 OSWorld-Verified 上,即 2025 年 7 月就地升级,改进任务质量/评分/基础设施)→ 前沿约 72–80%(2025 末/2026,如 Claude Opus 4.7 在 OSWorld-Verified 上 78.0%)。

**WindowsAgentArena(微软,2024)。** 在 OSWorld 基础上面向 Windows;154 任务;Azure 可并行 VM;可执行评估脚本。

### 领域四:通用助理 / 工具调用 / 深度研究

**GAIA(Mialon 等,2023)。** 466 个人工设计问题(300 私有测试,166 dev),按步数/工具分 3 个难度(L1 ≤5 步/1 工具;L2 5–10 步/多工具;L3 最多约 50 步)。验证:对归一化的短字符串/数字/列表答案做**准精确匹配**——无模拟环境。离线(但任务涉及实时浏览)。人类约 92%。注意:验证集在网上广泛可得,故高验证分可能反映记忆——应以私有测试结果为准。

**BrowseComp(OpenAI,2025 年 4 月)。** 1,266 个需持续多跳浏览的短答案问题;采用反向设计(从难找的答案倒推编写)。验证:精确/归一化短答案;canary GUID 用于污染检测。长程。GPT-4o 约 0.6–1.9%;OpenAI Deep Research 约 50%;o3 约 49%;前沿(GPT-5.4 Pro)约 89%。(Deep Research 在 64 次试验中对 16% 的任务 100% 解决、对 14% 的任务 0% 解决,显示难度双峰。)

**AssistantBench(Yoran 等,EMNLP 2024,arXiv:2407.15711)。** 214 个真实耗时网页任务,横跨 258 个网站的 525+ 页面。验证:自动答案匹配(准确率 + 精确率 + 精确匹配)。发布时无模型超过约 25 分;闭卷 LM 会幻觉(精确率低),早期网页 agent 接近零分。

**τ-bench / τ²-bench(Sierra,Yao 等,arXiv:2406.12045)。** 客服领域(零售、航空;τ²-bench 增电信)的工具-agent-用户交互。agent 使用领域 API 工具 + 政策准则;LLM 用户模拟器以信息不对称驱动对话。验证:**将最终数据库状态与标注目标状态做哈希比较**——检查真实结果而非仅工具调用语法。**pass^k** 指标(全部 k 次试验均成功)衡量可靠性——指数衰减暴露不一致。GPT-4o <50%;零售场景 pass^8 <25%。τ²-bench 增加双控(agent 与用户均有工具);前沿模型平均仍 <65%。已知问题:航空领域曾有错误真值(由 Claude Opus 4.5 团队修复),且该基准被指把空回答计为成功(结果有效性缺陷)。

**AgentBench(Liu 等,清华,ICLR 2024,arXiv:2308.03688)。** 8 个不同环境(OS、数据库、知识图谱、卡牌博弈、横向思维谜题、网购、网页浏览、家居)。多轮;按环境分别计指标后聚合。揭示商用与开源的巨大差距;长程推理、决策与指令遵循差是主要失败模式。

**Humanity's Last Exam(HLE)。** 横跨数学/人文/科学的 2,500 道专家题;有明确可验证解。属知识前沿基准;日益与 agentic 工具调用(搜索)评测结合,但本质并非 agent 基准。

## 建议
1. **衡量真实工程能力:** 用 SWE-bench Pro(公开 + 商业切分)与 Terminal-Bench 2.0,而非已饱和、疑似污染的 SWE-bench Verified。在固定脚手架下报告 Pass@1 并公开脚手架(分数随脚手架可摆动 10+ 分;同类模型在 SWE-bench Pro 公开切分上,研究脚手架约 23%,厂商自家脚手架约 80%)。
2. **网页 agent:** 不要依赖 WebVoyager 头部数字。用 Online-Mind2Web(条件允许配人工评测,否则用 WebJudge/o4-mini)与 Mind2Web 2 评测 agentic 搜索。始终用人工标注子集交叉核对 LLM 评判分数,因为评判的过度给分足以翻转排名(AgentRewardBench:最佳精确率下仍有 30% 轨迹被错误标记为成功)。
3. **工具调用/客服:** 用 τ²-bench 并报告 **pass^k(k≥4)**,而非仅 pass@1——可靠性崩塌才是阻碍部署的关键属性(pass@1 为 90% 的模型在 k=8 时一致性可能降至约 57%)。
4. **GUI/OS:** 用 OSWorld-Verified 与 AndroidWorld;报告步数预算(分数高度依赖最大步数),并对多个种子取平均(AndroidWorld 方差 ±20pp)。
5. **务必跑空操作/捷径基线**以检出结果有效性失效(如空回答 agent 通过 τ-bench 任务),并抽审"成功"轨迹是否存在奖励攻击;采信新基准前先套用 Agentic Benchmark Checklist(arXiv:2507.02825)。
6. **会改变建议的阈值:** 若某基准 SOTA 超过约 85% 且多家厂商聚集在几分内(类似 GPQA 式饱和),迁移至更难/保留的后继基准。若在你的任务分布上 LLM 评判与人工一致率低于约 80%,改用人工评测或基于细则的 Agent-as-a-Judge。

## 注意事项
- **榜单分数依赖脚手架与测试框架,且常为厂商自报**(如 OSWorld、SWE-bench 榜单混有自报与已验证行)。本文所引部分 2026 数字(如 "Claude Fable 5 在 SWE-bench Verified 上 95%"、"Claude Mythos Preview 在 OSWorld-Verified 上 79.6%"、"Claude Fable 5 在 SWE-bench Pro 上 80.3%")来自聚合榜单与产品博客,其模型名与数字未能与原始论文充分核对;请将最高的 2026 数字视为暂定。
- **"τ-bench 把空回答计为成功"** 出自 arXiv:2507.02825,该文将此类有效性缺陷的总体效应量化为"相对幅度最高可达 100%";某些二手来源流传的具体 "38% 任务" 数字未能与一手来源核对,故未予断言。
- **实时基准分数不随时间可复现**——网站变化、答案随时间变,且 CAPTCHA/反爬会介入;跨日期比较并不严谨。
- **"进展幻觉" 批评本身也是某一研究团队的框架**;后续评判(如 Ego2WebJudge)报告 WebJudge 与人工一致率更接近 76–78%,低于原始约 85%,故即便"可靠"的自动评估器仍有争议。
- 本报告在底层调研之外,专门聚焦验证机制与 2025–2026 SOTA;基准数字变动很快,引用前应再次对照官方榜单核实。
